# 加入屏幕类负样本（2026-11-05）

起因：换成 128 特征后，"television" 的误检变多了（尺度正则模型上平均从 3 个点增加到 120 个）。

做法：
- 在全部 16 个已保存模型上做成对比较：
  - 64 分辨率的模型 10 个；
  - 128 分辨率的模型 6 个。
  - 不重新训练，每个模型各用 3 组负样本打分（都用 pairwise-min）：
    - 当前默认；
    - 默认 + `monitor`；
    - 默认 + `monitor,screen`。
- AP 的参照是每个模型自己的 SAM 2 归属选择，规则与 `scripts/evaluate_run.py` 相同。
- 复现：`python outputs/negatives_screen_2026-11-05/compare.py`。结果写在 `results.json`，已有结果的模型会被跳过。

"monitor" 和 "television" 意思相近，所以只看 television 的下降并不公平。因此另外检查了 4 个场景里不存在、而且和新增负样本无关的物体：smartphone、tablet、printer、banana。

## 结果（16 个模型，相对于当前默认的变化）

| 指标 | 默认（均值） | + monitor | + monitor, screen | 变好的模型数 |
|---|---:|---:|---:|---:|
| laptop AP | 0.483 | +0.003 | **+0.007** | 15/16 |
| "notebook computer" AP | 0.466 | +0.002 | +0.004 | 11/16 |
| television 误检点数 | 48 | −39 | **−43** | 16/16 |
| smartphone 误检点数 | 1663 | −131 | **−554** | 16/16 |
| tablet 误检点数 | 8694 | −715 | **−1174** | 16/16 |
| printer 误检点数 | 4372 | −1882 | **−2035** | 16/16 |
| 文本选择留出 IoU | 0.774 | −0.001 | −0.001（中位数 0） | 变差 12/16，但幅度都很小 |
| 文本选择捕获率 | 0.614 | −0.017 | −0.017（中位数 −0.003） | 变差 15/16 |

- 128 分辨率的尺度正则模型上，television 误检从 185、97、77 个点降到 0、23、20 个。
- 和 4 个无关物体的检查结果一起看，这不只是因为 monitor 和 television 意思相近，打分的特异性确实整体提高了。

## 结论

- `monitor, screen` 已加入默认的场景负样本（`scripts/query_negatives.py`）。
- **代价**：文本选择的捕获率平均下降 0.017。原因是笔记本屏幕本身有一小部分点更像 "screen"，会被排除掉。IoU 基本不变。
  - 查询 "laptop screen" 这类包含 screen 的词时，`without_query` 会自动去掉 "screen" 这个负样本。
- **仍未解决**：tablet 在默认设置下有 8.7k 个点超过 0.5，加了负样本后仍有约 7.5k。平板和笔记本在 CLIP 里非常接近，这是 CLIP 本身的局限，加负样本解决不了。
- **注意**：此前各实验目录里的 `eval/*.json` 都是用旧默认负样本算的。之后再运行 `scripts/evaluate_run.py`，会使用新的默认负样本。
